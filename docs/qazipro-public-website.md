# QaziPro public website

## Scope

The standalone public site lives in `qazipro-website/`. It presents QaziPro's restaurant platform, Shopify work and full-stack services without coupling marketing pages to the restaurant runtime. The existing live `qazipro.com` site is not modified by this project.

## Local preview

1. Copy `qazipro-website/.env.example` to an ignored `.env.local`.
2. Use only the staging Supabase URL and a server-only staging secret key.
3. Set `STAGING_SUPABASE_PROJECT_REF` to the same project reference and `PUBLIC_LEADS_ENABLED=1`.
4. Run `npm install` and `npm run dev` inside `qazipro-website/`.
5. Open `http://localhost:3003`.

The lead API refuses to start when the configured Supabase hostname does not match `STAGING_SUPABASE_PROJECT_REF`. Never expose the secret key through a `NEXT_PUBLIC_` variable.

## Brand, portfolio and motion

- The supplied standalone QaziPro QR mark is used as the favicon and as a clean transparent mark in the header. The footer pairs that mark with the QaziPro name.
- The supplied WhatsApp artwork is tightly cropped for the global contact control. Clean transparent Shopify artwork is used on the homepage and Shopify service pages.
- Both approved founder portraits are used on `/about` with responsive crops and descriptive alternative text.
- `/portfolio` contains the project list supplied by QaziPro, grouped into Shopify, custom software and online ordering. Live screenshots are generated by `scripts/capture-portfolio.mjs`; unavailable, protected or unsuitable previews use a branded fallback.
- The site-wide motion layer provides Lenis inertial scrolling, hydration-safe entrance reveals, branded route/loading transitions, a lagged desktop cursor, pointer-origin liquid CTA fills, magnetic feedback, card spotlights, parallax depth, image zoom, a services ticker and scroll progress.
- The hydration mismatch reported on animated pages was fixed by deferring imperative DOM decoration until after streamed-route hydration. Production-browser navigation and console checks cover this regression.
- All non-essential motion is disabled by `prefers-reduced-motion`.
- **Client portal** is an explicit outlined CTA in the desktop header, a full-width mobile-menu action and a footer link. Its destination is configured by `NEXT_PUBLIC_CLIENT_PORTAL_URL` and safely defaults to `https://portal.qazipro.com`.
- Testimonials remain unpublished until QaziPro supplies approved client names, quotes and profile images. The site never fabricates this evidence.

## Lead workflow

Contact, demo, quote and onboarding inquiries post to the same-origin `/api/leads` route. Server-side validation, body limits, a honeypot, minimum completion time, duplicate protection and database-backed rate limiting run before a lead is written. Leads are stored in staging `platform_demo_requests` and appear in the Super Admin **Website leads** inbox for staff with `onboarding.manage`.

Commercial terms and signatures are not collected by the public form. Approved clients receive the existing private, time-limited Super Admin agreement link. Optional email notification uses a server-side HTTPS webhook; the database remains authoritative if notification delivery fails.

## Preview and cutover

Preview deployments must keep `APP_ENVIRONMENT=staging`; they emit `noindex` and disallow crawlers.

Latest verified preview: `https://qazipro-public-website-lc073jt0t.vercel.app` (`dpl_WoC7hwsbTVw1JarHRTBDfSnaQibN`). It is a Vercel-protected preview target, emits `noindex`, keeps the live domain untouched, and passed the final build plus authenticated 18-route desktop/mobile, accessibility, reduced-motion, metadata, security-header, console, overflow and visual checks on 2026-09-23.

Before a production cutover:

1. Obtain final founder approval for copy, legal pages, screenshots and contact details.
2. Add approved case studies and testimonials only when evidence and permission exist.
3. Configure production analytics/consent and a verified email notification provider if required.
4. Create production-only lead credentials through a reviewed secret-manager workflow.
5. Run desktop/mobile visual, accessibility, form-delivery and SEO checks on the final domain.
6. Back up the current site, lower DNS TTL, verify redirects, then change DNS only in a scheduled cutover window.
7. Monitor forms, logs, indexing and Core Web Vitals after launch; retain a rollback target.

Do not point the preview deployment at Production Supabase and do not replace live `qazipro.com` without explicit approval.
